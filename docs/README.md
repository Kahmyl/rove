# Rove documentation

Rove is a task and workflow assistant. These documents describe the product being built, the design that should serve it, and how changes are verified. Rove has not shipped a production release. Document titles and filenames identify their subject, not a product version, implementation milestone, phase, gate, or ticket.

## Design is not implementation status

The engineering documents specify target behavior. Existing code supplies reusable foundations but has not thereby been certified to satisfy the whole product model. A rename, passing regression test, or updated document is not proof of an untested capability.

The bounded task-lifecycle correction was implemented from baseline `3f9d74bb011b52caf92bd857a8fd8922eb3b7a8f`. Ordinary model tasks can now start and continue without a Runtime session or browser identity; a task-scoped MCP capability attaches one correlated Runtime session only when browser work is requested. Browser loss does not close the Codex conversation, Stop interrupts only the active turn, and launch/message admission checks the live host account and selected model before durable task acceptance. Existing browser-backed tasks retain their stored session capability compatibility and exact task/thread/session routing.

The current Runtime also implements task-owned page groups within one managed host per persistent browser workspace. Each attached Runtime session sees only its owned pages; explicit opens and opener-correlated popups inherit that ownership while the group is live; commands and events route through the session/page map; and detaching one group closes only its pages while fencing delayed attribution. The final group releases the host/profile lease only after verified persistent-process death. Independent page operations may overlap. Physical focus operations and human takeover use host-scoped coordination; takeover presents the requesting page, and return invalidates all groups' grounding authority before mutation admission reopens. Unattributed restored or late pages are quarantined rather than assigned from UI selection or browser focus.

The companion now also implements local Workflow environments in the existing task-engine SQLite database. A name is enough to create one and enter its persistent Home immediately; sparse Workflows remain valid. Home projects exact associated recent tasks, stable task Results, and task-owned attention from the existing ledger, while Outputs aggregates those same Result records without introducing another content store. Users can start ordinary tasks in the Workflow; optionally inspect or edit structured context; explicitly choose whether the selected immutable revision is shared with Codex; archive and restore the Workflow; and promote one identified attachment-free conversation item through a reviewed Save to Workflow boundary. Immutable revisions, expected-revision conflicts, operation identities, local promotion provenance, and the exact context revision/digest applied to each new turn are durable across restart. Active-turn steering keeps its already-applied context until the next turn boundary.

Structured task results are also implemented locally. Users can save selected assistant responses as findings, drafts, reports, journeys, or explicitly reviewed actions; select an exact immutable revision/digest for a later turn even if the current draft is edited; and promote an exact result revision through the existing Save to Workflow boundary. Selected Output content enters the model as bounded user/evidence working context, not developer authority; approved Workflow guidance and host action-safety policy keep their existing authority. Action authorization registers the digest of recipient/content/attachment/target/scope material with the exact Runtime session before dispatch. Runtime effect-journal truth, rather than assistant prose, advances an action through authorized, possibly dispatched/unresolved, confirmed, or failed state.

Requested page video is implemented for task-owned pages in Agent, Companion, and Capture modes. The persisted lifecycle, explicit privacy acknowledgement, sensitive-control refusal, interrupted-recording recovery, and playable WebM finalization have deterministic tests. Browser-window capture remains unavailable because one shared window can expose another task or browser chrome; packaged OS permissions, disk exhaustion, and real permission revocation remain qualification gaps.

The Settings surface also provides deliberate device-local backup export. It uses SQLite's online backup operation for the live task, Workflow, and result ledger, copies allowlisted Runtime history and artifacts, records included, missing, changed, and excluded entries in a manifest, and excludes Rove-managed credential, capability-key, browser-profile, and task-workspace stores. Restore remains unavailable until archive, checksum, path, ownership, and compatibility validation exists; export does not claim cross-device Workflow synchronization.

This is implementation evidence for task independence, lazy browser attachment, bounded page-group concurrency, useful device-local Workflow context, stable result follow-up, requested page recording, and explicit local export. A page group is not an account or security boundary because pages in a workspace still share browser-context state. The evidence does not establish exhaustive detection of authentication changes caused by ordinary navigation or complete multi-step clipboard isolation. It also does not certify automatic structuring of every artifact, workflow portability, account/workflow synchronization, browser-window capture, restore, or a replacement UI/browser stack. Existing local task, Workflow, result, recording, and execution stores remain device-local product state, not a workflow synchronization service.

## Decisions still requiring implementation evidence

The account/workflow-sync provider and any replacement UI or browser library remain bounded implementation choices. Browser-window capture requires an isolated ownership boundary and platform qualification rather than a different label on page recording. Their required behavior is specified here. Broader shared-state coordination beyond the implemented page/focus/takeover boundaries still requires concrete product scenarios and evidence. Do not adopt the earlier full task-sync proposal, move credentials to the cloud, or add another agent framework merely to complete those choices.
